AI Receipt Processing — Accounting System

What We're Building
A web-based system where users upload receipt images/PDFs, Gemini Vision extracts the line items, the system matches them against a product database, and outputs a structured Google Doc report.

APIs Needed
Gemini (Primary AI)

Model: gemini-1.5-flash (vision capable, fast, cheap)
Usage: Send receipt image → get structured JSON of line items
Prompt engineering: Extract {item_name, barcode, quantity, unit_price, total}
SDK: google-generativeai Python package

Google Docs API

Create a new Doc per receipt
Write structured table: item name, barcode, price, qty, total
Return shareable link
Auth: Service Account (simplest for server-to-server)

Google Drive API

Needed alongside Docs to set sharing permissions


Database Schema
sql-- Products (the central reference DB)
products (
  id, barcode VARCHAR UNIQUE, name, category,
  unit_price DECIMAL, unit, supplier, created_at
)

-- Receipts (each upload)
receipts (
  id, uploaded_by, image_url, status ENUM(pending/processing/done/failed),
  raw_extraction JSONB,  -- Gemini raw output
  created_at
)

-- Receipt Line Items (matched)
receipt_items (
  id, receipt_id FK, product_id FK NULLABLE,
  extracted_name, extracted_barcode, extracted_qty,
  extracted_unit_price, matched BOOLEAN,
  match_confidence FLOAT, doc_url
)

Matching Engine Logic
This is the most critical part. Here's the matching priority:

Exact barcode match → confidence 1.0
Exact name match (case-insensitive) → confidence 0.95
Fuzzy name match via rapidfuzz → confidence score from library
No match → flag as unmatched, still include in output

Threshold: anything below 0.75 confidence = "unmatched, needs review"

Google Docs Output Format
Each generated doc will contain:

Header: Receipt date, uploaded by, processing timestamp
Table: Item # | Product Name | Barcode | Qty | Unit Price | Total | Match Status
Summary: Total items, matched count, unmatched count, grand total
Footer: "Generated by AI Receipt System"
